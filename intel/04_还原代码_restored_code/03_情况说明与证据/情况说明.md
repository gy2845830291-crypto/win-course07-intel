# 核心代码还原情况说明

## 一、整理范围

本文件夹只整理核心代码及其直接证据，不把界面、资源图片、普通配置文件等外围内容计入核心成果。

当前源码级核心完成度约 **65%–70%**，未还原部分约 **30%–35%**。

## 二、已经还原的核心代码

### 1. 动态导入解析

- RVA `0x21EF0–0x220F1`。
- 已恢复 `GetModuleHandleA → LoadLibraryA → GetProcAddress` 流程。
- 正常 API 失败时，原代码遍历 PEB 模块链与导出表。
- 导出名哈希为 FNV-1a：seed `0x811C9DC5`，prime `0x01000193`。
- 固定哈希 `0x54A79208` 已解析为 `ntdll!RtlNtStatusToDosError`。

### 2. 内部文件访问层

- `0x22B00`: seek。
- `0x22B60`: read_exact。
- `0x22BF0`: write_exact。
- `0x22CB0`: get_size32。
- `0x22D20`: close。
- `0x22D8E`: CreateFileW/open 路径。

### 3. 解包核心

- `0x2BF10–0x2C0B4`: 反向位流初始化。
- `0x2C0C0`: peek_bits。
- `0x2C0E0`: read_bits。
- `0x2C100`: bit container 反向重新装载。
- `0x2D470`: FSE/tANS 状态转换。
- `0x2D4C0–0x2DBD8`: 三状态 sequence decoder。

该解码器维护 literal length、match length、offset 以及 repeat offsets，并执行 16/32 字节 match-copy，结构属于 Zstandard-style FSE 解压核心。

### 4. 校验状态核心

- FAIL immediate `0x54D85BC4` 最终生成 `0xC000B00A`。
- PASS immediate `0x5A705B64` 最终生成状态 `0`。
- forced-pass 实跑得到 `rv=1`、`status=0x0`。
- 完整失败链已定位到 `0x2B108C → FAILENC → MBA`。

### 5. 数量

- `.pdata` 识别函数：1165 个。
- 相对旧镜像恢复/改变函数：367 个。
- 其中此前全零函数：366 个。
- 恢复的函数范围字节：157,580。
- IAT 槽：104 个。
- 静态 API 引用：215 个。

已还原源码集中在 `01_已还原代码/DENS102_RECONSTRUCTED_CORE.cpp`。

## 三、没有还原的核心代码

### 1. `0x0FB14`

- 字节已取得。
- 所在函数范围 `0xD8A0–0xFDD3`。
- 仍属于高度虚拟化控制流，尚未恢复为稳定 C/C++ 语义。

### 2. `0x19B931`

- EP 的第二个调用目标。
- 当前仍含 Ace VM、伪调用、标志栈操作及 `retf` 等不透明结构。
- 需要在运行时解密窗口冻结后重新抓取。

### 3. `0x185F49`

- EP 的第三个调用目标。
- 使用栈重写、伪返回地址与 opaque arithmetic。
- 静态快照不足以还原真实控制流。

### 4. 自然通过选择器

- 已知一旦进入 `0x2B108C` 就会落入失败编码链。
- 尚未找出哪个真实字段、签名比较或布尔值使执行流避开该入口。
- forced-pass 成功不等于自然选择器已经恢复。

### 5. post-pass `.uyB`

- 尚未取得可验证字节。
- 没有使用空文件、全零数据或推测内容冒充该区域。
- 需要 forced-pass 与 Ace suspend-first 在同一有效时间窗串联。

原始切片、目标入口切片及反汇编放在 `02_未还原代码`。

## 四、难度说明

已完成部分难度约 **8/10**；剩余部分约 **9.5/10**。主要原因：

1. 解密代码存在时间可能短于约 150 毫秒。
2. 真正代码位于 private buffer，不直接等同于磁盘 `.ace0`。
3. 不同快照存在 `+0x2000/+0x4000` 位移。
4. 入口使用 VM、异常驱动、自修改和栈重写。
5. `.uyB` 只在通过态后发生有效变化。
